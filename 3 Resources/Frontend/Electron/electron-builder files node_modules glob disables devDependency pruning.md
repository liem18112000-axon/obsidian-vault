# electron-builder files node_modules glob disables devDependency pruning

By default electron-builder does **not** glob-copy `node_modules`: it inserts a `!**/node_modules` exclusion, then walks the real dependency graph (its `node-dep-tree` helper) and copies only packages reachable from `dependencies` in package.json. `devDependencies` are pruned automatically — no `npm ci --omit=dev` prune step needed (and you must NOT prune before the build if `electron-builder` is itself a devDependency; you'd delete the tool).

**Listing `"node_modules/**/*"` yourself in `build.files` defeats that.** Pattern matching is last-match-wins (.gitignore semantics) and your explicit include is appended after the default exclusion, so the whole folder is copied verbatim, devDependencies included. In Vinnstack (Next.js + Electron) this shipped a full extra copy of `electron` itself (~270MB prebuilt binary, never needed at runtime since electron-builder bundles its own runtime), plus electron-builder, typescript, vitest, testing-library, tailwindcss.

**Fix:** delete the `node_modules/**/*` line and let the default handling run.

Verified by reading app-builder-lib source rather than docs — `fileMatcher.js` `getMainFileMatchers`, `platformPackager.js` `copyAppFiles`, `util/appFileCopier.js` `computeNodeModuleFileSets`, `util/packageDependencies.js` `createLazyProductionDeps`. That source sits in `node_modules/app-builder-lib` of any install, so it is checkable in any project.

Caveat worth re-verifying per build: an earlier inspection of the same repo (asar:false) found the devDependencies *absent* from `resources/app/node_modules` despite the explicit glob. Check the actual packaged tree rather than assuming either outcome.
