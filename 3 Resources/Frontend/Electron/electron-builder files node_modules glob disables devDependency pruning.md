# electron-builder files node_modules glob disables devDependency pruning

Listing `"node_modules/**/*"` explicitly in electron-builder's `build.files` array in package.json disables its built-in smart production-dependency-tree walk.

By default (when you do NOT list node_modules in `files`), electron-builder inserts a `!**/node_modules` exclusion pattern automatically, then separately walks the actual dependency graph (via its `node-dep-tree` helper) to copy only packages reachable from `dependencies` in package.json — `devDependencies` are never touched. This is documented electron-builder behavior, but easy to accidentally defeat.

If you list `node_modules/**/*` yourself, pattern-matching semantics are "last match wins" (like .gitignore), and your explicit include is appended after the default exclusion, so it wins — the whole node_modules folder gets copied verbatim, `devDependencies` included. In a Vinnstack (Next.js + Electron) app this meant the packaged .exe carried a full extra copy of `electron` itself (~270MB, the prebuilt Electron binary that ships as a devDependency for local dev — never needed at runtime since electron-builder bundles its own Electron runtime), plus electron-builder, typescript, vitest, testing-library, tailwindcss, etc.

Fix: remove the `node_modules/**/*` line entirely and let electron-builder's default node_modules handling run. Verified by reading app-builder-lib source directly (`fileMatcher.js` getMainFileMatchers, `platformPackager.js` copyAppFiles, `util/appFileCopier.js` computeNodeModuleFileSets, `util/packageDependencies.js` createLazyProductionDeps) rather than trusting docs alone — the source is inside `node_modules/app-builder-lib` of any electron-builder install, so this is checkable in any project.
