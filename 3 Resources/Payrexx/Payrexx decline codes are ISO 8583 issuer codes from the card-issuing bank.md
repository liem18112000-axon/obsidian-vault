# Payrexx decline codes are ISO 8583 issuer codes from the card-issuing bank

Payrexx decline codes are two-character ISO 8583 codes generated by the card-issuing bank, not by Payrexx itself. The official enumeration (~50 codes) lives in the merchant docs: https://docs.payrexx.com/merchant/english/payment/payment-status

Common ones: 51 = insufficient funds, 54 = card expired, 82 = CVV mismatch, 1A = 3-D Secure authentication required (Visa), 05 = issuer refuses, 91 = issuing bank unreachable.

Two distinct status vocabularies exist: the merchant-UI payment statuses (15, incl. Timeout, Pending, Charged, Dispute states) and the API transaction statuses (12: waiting/confirmed/cancelled/declined/...). Don't conflate them when debugging.

Deep extraction (2026-07-24, full verbatim table in luz_store/docs/luz-157476/PAYREXX-ERROR-CODES.md): the codes are displayed in the Payrexx **transaction detail view** (reason + code side by side) — so a backoffice lookup per stored charge_transaction_id reveals the decline code for any historical failed charge, even though the API never returns it. Draft LUZ-157476 category distribution over all 51 codes: blocked-by-issuer 26, invalid-details 12, other 8, insufficient-funds 5, card-expired 1. The API wrapper prose looks like shortened per-code reason text (e.g. 'Your card has expired.' ↔ code 54) — unverified hypothesis that message is derived from the code server-side. Special attention for recurring billing: codes R/R1/R3 = cardholder cancelled recurring payments — operationally equivalent to card-expired (customer must re-register card).
